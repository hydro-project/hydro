Expand description

Directories that a dynamically linked artifact built into the per-job artifact dir job_debug (e.g. jobs/<name>/debug) needs on its library search path (rpath or LD_LIBRARY_PATH) to load the trybuild dylib whose cargo package is dylib_package_name. shared_debug is the shared target’s debug/ that the job mirrors.

Every returned path must stay valid for the artifact’s whole lifetime, which outlives the build (the binary is exec’d by the deployment later; the simulator dlopens its cdylib after the build returns). Job dirs are keyed by generated-source hash, so tests whose programs are identical share one; a later build in the same job dir repopulates its build/ (see populate_job_build_dir), so nothing under job_debug/build/ may be referenced. The dylib’s home is instead the shared prebuilt state, which only changes under the exclusive prebuild lock.

Cargo uplifts the dylib into job_debug under its unhashed lib<name>.so filename, which satisfies the loader whenever the artifact links against that name. With __CARGO_DEFAULT_LIB_METADATA set, however, the artifact links against the hash-suffixed lib<name>-<hash>.so:

  • under the legacy layout every variant, hashed or not, lives in deps/, which job_debug/deps symlinks to once at job setup;
  • under the new layout deps/ no longer exists and the uplift is renamed to the unhashed name, so the hashed file only exists in the dylib unit’s <shared_debug>/build/<dylib_package_name>/<hash>/out/ dir. Every such unit dir is included; hashed names are unique per unit so this is unambiguous, and unhashed names resolve from job_debug (listed first) before any unit dir.
