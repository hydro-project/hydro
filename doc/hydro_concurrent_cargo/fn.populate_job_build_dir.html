pub fn populate_job_build_dir(
    job_debug: &Path,
    shared_debug: &Path,
) -> JobBuildGuard
Expand description

Populate the per-job build/ directory from the shared build/ directory. Returns a guard that holds the job lock — keep alive for the entire final build. This prevents races between processes building the same job concurrently.

The shared build/ is mirrored two levels deep: each top-level directory is recreated job-locally and its children are symlinked to the shared copies. Anything the final build reads is the prebuilt, immutable shared state; anything it creates or replaces lands in the job-local directory instead of racing other jobs. This is the same structure under both layouts:

  • Legacy (build/<pkg>-<hash>/{build-script-build,out,output,...}): cargo re-links build-script-build even on fresh builds; with per-child symlinks that replaces the job-local link, not the shared file.
  • New (build/<pkg>/<unit-hash>/{fingerprint,out,run}): the final build’s own example unit is created job-locally. This matters because concurrent jobs can compile the same cargo unit — the simulator builds the fixed sim-dylib example in every job (varied only via include!(env!(..)), which affects freshness but not the unit hash) — so sharing build/ wholesale would have them write, and uplift, the same out/ files.
