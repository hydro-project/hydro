1//! Shared locking and job directory utilities for parallel cargo builds in Hydro.
2//!
3//! This crate provides the coordination primitives for running multiple cargo
4//! builds concurrently against a shared target directory using per-job symlinked
5//! directories.
6//!
7//! # Why
8//!
9//! Hydro compiles each generated program (one per deployed process, sim test, ...)
10//! as an example of a generated trybuild project. Cargo allows a single build per
11//! target directory (it takes an exclusive lock on it), so compiling those programs
12//! concurrently through cargo directly would serialize them. At the same time they
13//! all share the same, expensive dependency graph, so giving each its own target
14//! directory would recompile everything per program.
15//!
16//! # The trick: prebuild once, then share the artifacts without cargo's lock
17//!
18//! Builds run in two phases, coordinated by this crate's own locks:
19//!
20//! 1. **Prebuild** (exclusive `.prebuild.lock`): one cargo build compiles every
21//!    dependency — including the trybuild dylib that the generated programs link
22//!    against — into the *shared* target dir. While it runs, no final build is in
23//!    flight, so it may freely write shared state.
24//! 2. **Final builds** (shared `.prebuild.lock`): many cargo builds run
25//!    concurrently, each with its *own* target-dir root under `jobs/<JOB>/`, so
26//!    cargo's locks are per job and never contend. The shared, prebuilt state is
27//!    made visible inside each job dir via symlinks. This is safe without cargo's
28//!    lock only because of an invariant the two phases establish: **a final build
29//!    reads shared state but never writes it** — everything it reads is fresh (the
30//!    prebuild just built it, with identical features/rustflags, so cargo finds the
31//!    fingerprints up to date), and everything it creates (its own example unit,
32//!    its uplifted artifacts) has a job-unique path. Switching configuration
33//!    (features, rustflags, toolchain) takes the lock exclusive again, draining all
34//!    in-flight final builds before the prebuild rewrites shared state.
35//!
36//! Unrelated cargo processes building in the shared target dir (a developer's
37//! `cargo build`, an IDE) are kept out the same way cargo keeps itself out: this
38//! crate holds the shared target dir's own `.cargo-build-lock` **shared** for the
39//! whole prebuild + final build, and cargo takes that file **exclusive** for any
40//! build there, so the two mutually exclude ("Blocking waiting for file lock on
41//! build directory"). This is also why *every* cargo spawned by this crate —
42//! prebuild included — gets a `jobs/*` root rather than the shared dir: a child
43//! cargo using the shared dir would wait forever on the lock its own parent holds.
44//!
45//! # Configurations and the `__CARGO_DEFAULT_LIB_METADATA` optimization
46//!
47//! A *configuration* is a (crate, features, rustflags, compiler) tuple. Cargo hashes
48//! all of these into the filenames of rlibs, so artifacts of different
49//! configurations coexist in the shared `deps/` and are cached side by side — with
50//! one exception: the filename of a path package's **dylib** carries no hash
51//! (`libX_dylib.so`), so every configuration would want to write the same file.
52//! The trybuild dylib is thus the single shared resource configurations fight
53//! over, and the design has two modes (see [`run_prebuild`], [`dylib_lib_name`]):
54//!
55//! - **Default**: the fingerprint of rustflags + compiler version
56//!   ([`toolchain_fingerprint`]) is baked into the dylib's `[lib] name`, so
57//!   different toolchains/rustflags get distinct files. Features are not part of
58//!   the name, so switching features *replaces* the dylib: there is a single
59//!   `.prebuild.lock`, every build holds it shared through its final build, and a
60//!   configuration switch takes it exclusive — draining all in-flight builds
61//!   before the prebuild renames the manifest and rebuilds. Concurrency is
62//!   therefore limited to builds of **one configuration at a time**: while test
63//!   binary A (features `{sim}`) has final builds in flight, test binary B
64//!   (features `{sim, deploy}`) blocks until they finish, then rebuilds the dylib,
65//!   then A blocks on B — alternating binaries ping-pong the shared dylib.
66//! - **`__CARGO_DEFAULT_LIB_METADATA=1`** (set in CI): this undocumented cargo
67//!   variable (used by rust-lang/rust's bootstrap) makes cargo hash dylib filenames
68//!   too (`libX_dylib-<hash>.so`), so every configuration's dylib is a distinct
69//!   file and the manifest never changes. Shared state becomes append-only across
70//!   configurations — nothing one configuration writes is ever read by another —
71//!   so the lock can be split per configuration: one `.prebuild-<key>.lock` each,
72//!   with the cross-configuration `.global-prebuild.lock` taken only around a
73//!   prebuild's actual `cargo build` so two prebuilds never write `deps/` at the
74//!   same time. The concurrency this unlocks: **final builds of different
75//!   configurations run simultaneously**, and a prebuild for one configuration
76//!   runs while another configuration's final builds are in flight. For nextest,
77//!   which runs many test binaries with differing feature sets at once, that is
78//!   the difference between the binaries serializing on each other and all of them
79//!   proceeding in parallel — and every configuration's dylib stays cached instead
80//!   of being rebuilt on each switch.
81//!
82//! Why a prebuild for configuration B may overlap configuration A's final builds:
83//! cargo only writes a unit's files when the unit is *dirty* (fresh units are not
84//! touched at all; the legacy-layout `build-script-build` re-link rewrites only the
85//! job-local uplift). B's prebuild therefore writes B-specific units, which have
86//! B's hashes and are never read by A, plus any unit *shared* with A that is dirty.
87//! A's final builds read only units A's own prebuild completed, so a shared unit is
88//! fresh for B — unless its inputs changed since A's prebuild. That is the
89//! precondition: all concurrent builds must come from one source state. Within a
90//! test run it holds (test binaries are built before any runs, and the prebuild
91//! stamp is keyed on the binary's mtime); running test processes from two
92//! different source states at once is unsupported in either mode (in default mode
93//! A's `--frozen` final builds would panic with "unexpected recompilation"). The
94//! prebuild-vs-prebuild case is different — two configurations can both be dirty
95//! on the same not-yet-built shared unit — which is exactly what
96//! `.global-prebuild.lock` serializes.
97//!
98//! Mixing builds with and without the variable against one target dir is
99//! unsupported: they would rename the shared manifest under different locks.
100//! Because the hashed dylib name is what the final artifacts link against
101//! (`DT_NEEDED`), loader search paths must include wherever that hashed file
102//! lives; see [`dylib_search_dirs`].
103//!
104//! # Layouts
105//!
106//! Cargo's new build-dir layout (`-Zbuild-dir-new-layout`, default on current
107//! nightly) moves everything under `build/<pkg>/<unit-hash>/`; see
108//! [`BuildDirLayout`] (detected at compile time by `build.rs`). The same job-dir
109//! structure works for both layouts: the job's `build/` is a real directory two
110//! levels deep whose children are symlinks, so writes cargo makes at that level
111//! (legacy: re-linking `build-script-build`; new: the job's own example unit, which
112//! for the simulator is the *same* cargo unit in every job) stay job-local.
113//!
114//! ```text
115//! LEGACY LAYOUT (stable)                                       NEW LAYOUT (nightly -Zbuild-dir-new-layout)
116//!
117//! target/                                                      target/
118//! ├── .prebuild.lock       hydro's own lock (see above)        ├── .prebuild.lock
119//! ├── debug/               <-- SHARED prebuilt state           ├── debug/               <-- SHARED prebuilt state
120//! │   ├── .cargo-build-lock   hydro holds SHARED;              │   ├── .cargo-build-lock   (same: excludes unrelated cargo)
121//! │   │                       unrelated cargo takes EXCLUSIVE  │   ├── (no .fingerprint/, no deps/)
122//! │   ├── .fingerprint/                                        │   ├── build/
123//! │   │   └── <unit>-<h>/     one dir per unit                 │   │   └── <pkg>/          one dir per package
124//! │   ├── deps/               rlibs + dylibs, hashed names     │   │       └── <h>/        one dir per unit
125//! │   │   ├── libfoo-<h>.rlib                                  │   │           ├── fingerprint/
126//! │   │   └── libX_dylib-<h>.so   SHARED prebuilt dylib        │   │           ├── out/    rlibs, dylibs, .o
127//! │   └── build/              build scripts + OUT_DIR          │   │           │   └── libX_dylib-<h>.so   SHARED prebuilt dylib
128//! │       └── <pkg>-<h>/                                       │   │           └── run/    build script runs
129//! │           ├── build-script-build                           │   └── libX_dylib.so       uplift, UNHASHED name
130//! │           ├── out/                                         │
131//! │           └── output                                       ├── jobs/
132//! │                                                            │   ├── prebuild/           (hydro's exclusive lock held)
133//! ├── jobs/                                                    │   │   └── debug/
134//! │   ├── prebuild/           (hydro's exclusive lock held)    │   │       ├── .cargo-lock, .cargo-build-lock   (job-local)
135//! │   │   └── debug/                                           │   │       ├── .fingerprint -> target/debug/.fingerprint  (unused)
136//! │   │       ├── .cargo-lock                   (job-local)    │   │       ├── deps         -> target/debug/deps          (unused)
137//! │   │       ├── .fingerprint -> target/debug/.fingerprint    │   │       └── build        -> target/debug/build    writes through
138//! │   │       ├── deps         -> target/debug/deps            │   │
139//! │   │       └── build        -> target/debug/build           │   └── <JOB>/              (one per generated program)
140//! │   │                           (whole dir, writes through)  │       └── debug/
141//! │   │                                                        │           ├── .cargo-lock, .cargo-build-lock   (job-local)
142//! │   └── <JOB>/              (one per generated program)      │           ├── .fingerprint -> ...              (unused)
143//! │       └── debug/                                           │           ├── deps         -> ...              (unused)
144//! │           ├── .cargo-lock                   (job-local)    │           ├── build/                           REAL dir
145//! │           ├── .fingerprint -> target/debug/.fingerprint    │           │   └── <pkg>/                       REAL dir
146//! │           ├── deps         -> target/debug/deps            │           │       ├── <h1> -> target/debug/build/<pkg>/<h1>  prebuilt
147//! │           ├── build/                        REAL dir       │           │       └── <h2>/                    REAL: this job's
148//! │           │   └── <pkg>-<h>/                REAL dir       │           │           └── out/libsim_dylib-<h2>.so    own example
149//! │           │       ├── build-script-build -> shared         │           ├── libX_dylib.so       job's uplift of the SHARED dylib
150//! │           │       ├── out                -> shared         │           └── examples/<JOB>      FINAL artifact
151//! │           │       └── output             -> shared         │
152//! │           └── examples/<JOB>      FINAL artifact           │
153//! ```
154//!
155//! `libX_dylib` is the *shared* trybuild dylib (the user crate + `hydro_lang` built
156//! once by the prebuild) that every final artifact links against; `libsim_dylib` is
157//! a *final* per-job artifact (the simulator's `cdylib`) that links against it.
158//!
159//! Loader search paths (rpath / `LD_LIBRARY_PATH`) for `libX_dylib` are computed by
160//! [`dylib_search_dirs`] and only ever name state that outlives the build: the
161//! job's `debug/` and the shared location (`deps/` on legacy, the shared unit `out/`
162//! dirs on new) — never `jobs/<JOB>/debug/build/`, which is repopulated on every
163//! build (and job dirs are shared by tests whose generated programs are identical).

173/// The filesystem layout cargo uses for intermediate build artifacts.
174///
175/// Detected at compile time by this crate's build script, which inspects the
176/// shape of its own `OUT_DIR` (see `build.rs`). Use [`build_dir_layout`] to
177/// query it.
178#[derive(Debug, Clone, Copy, PartialEq, Eq)]
179pub enum BuildDirLayout {
180    /// The stable layout: `debug/{.fingerprint,deps,build,...}`, with final
181    /// artifacts uplifted into `debug/` and dependency dylibs in `debug/deps/`.
182    Legacy,
183    /// The layout behind `-Zbuild-dir-new-layout` (default on current nightly):
184    /// all intermediates (fingerprints, rlibs, build script outputs) live under
185    /// `debug/build/<pkg>/<hash>/{fingerprint,out,run}/`, and final artifacts
186    /// — including dependency dylibs — are uplifted into `debug/`.
187    New,
188}
189
190/// The [`BuildDirLayout`] used by the toolchain that compiled this crate.
191///
192/// The runtime cargo invocations coordinated by this crate use the same
193/// toolchain (rustup pins the toolchain for the whole process tree), so the
194/// compile-time verdict matches the layout of the builds we coordinate;
195/// switching toolchains recompiles this crate and re-runs the detection.
196pub fn build_dir_layout() -> BuildDirLayout {
197    if cfg!(new_build_dir_layout) {
198        BuildDirLayout::New
199    } else {
200        BuildDirLayout::Legacy
201    }
202}

208/// Log a timestamped message to the build coordination log.
209pub fn log_build_event(project_dir: &Path, msg: &str) {
210    let log_path = project_dir.join("build-coordination.log");
211    let mut file = fs::OpenOptions::new()
212        .create(true)
213        .append(true)
214        .open(log_path)
215        .unwrap();
216    let now = SystemTime::now()
217        .duration_since(std::time::UNIX_EPOCH)
218        .unwrap()
219        .as_millis();
220    let thread_id = std::thread::current().id();
221    let _ = writeln!(file, "[{now}ms] [{thread_id:?}] {msg}");
222}

228/// Global prebuild serialization lock (in-process).
229static GLOBAL_PREBUILD_LOCK: parking_lot::RwLock<()> = parking_lot::RwLock::new(());
230
231/// Per-key in-process prebuild locks, mirroring the per-key lock files (see [`run_prebuild`]).
232static DEP_BUILD_LOCKS_PER_KEY: LazyLock<Mutex<HashMap<String, &'static parking_lot::RwLock<()>>>> =
233    LazyLock::new(|| Mutex::new(HashMap::new()));
234
235fn get_dep_lock(key: &str) -> &'static parking_lot::RwLock<()> {
236    let mut map = DEP_BUILD_LOCKS_PER_KEY.lock().unwrap();
237    map.entry(key.to_owned())
238        .or_insert_with(|| Box::leak(Box::new(parking_lot::RwLock::new(()))))
239}
240
241/// Per-job-dir mutexes for serializing job dir setup/population within a process.
242static JOB_DIR_LOCKS: LazyLock<Mutex<HashMap<PathBuf, &'static Mutex<()>>>> =
243    LazyLock::new(|| Mutex::new(HashMap::new()));
244
245fn get_job_dir_lock(job_dir: &Path) -> &'static Mutex<()> {
246    let mut map = JOB_DIR_LOCKS.lock().unwrap();
247    map.entry(job_dir.to_owned())
248        .or_insert_with(|| Box::leak(Box::new(Mutex::new(()))))
249}

255/// Guard holding the shared target dir's `.cargo-build-lock` **shared**.
256///
257/// Cargo takes this same file **exclusive** for the duration of any build in that target dir
258/// (the "build directory" lock, cargo ≥ 1.98 and nightly), so holding it shared for the whole
259/// prebuild + final build mutually excludes us from unrelated cargo processes building there
260/// — which would otherwise race our symlinked writes into `deps/`, `.fingerprint/` and
261/// `build/` without any lock between us. Concurrent hydro builds all hold it shared and so
262/// proceed together.
263///
264/// Consequence: no cargo spawned while this is held may use the shared target dir as its
265/// `--target-dir` — it would block forever on the lock its own parent holds. Every cargo we
266/// spawn (prebuild included) therefore gets its own root under `jobs/`, with the shared
267/// state reached through symlinks.
268pub struct CargoBuildLock {
269    _file: fs::File,
270}
271
272impl CargoBuildLock {
273    pub fn lock_shared(lock_path: &Path) -> Self {
274        let file = fs::OpenOptions::new()
275            .read(true)
276            .write(true)
277            .create(true)
278            .truncate(false)
279            .open(lock_path)
280            .unwrap();
281        file.lock_shared().unwrap();
282        CargoBuildLock { _file: file }
283    }
284}

290/// Guard holding both in-process and file locks for prebuild coordination.
291pub struct PrebuildGuard {
292    _rw_guard: RwGuard,
293    _global_guard: Option<parking_lot::RwLockWriteGuard<'static, ()>>,
294    _global_file: Option<fs::File>,
295    _file: fs::File,
296    lock_dir: PathBuf,
297}
298
299#[expect(
300    dead_code,
301    reason = "variants hold lock guards that are released on drop"
302)]
303enum RwGuard {
304    Read(parking_lot::RwLockReadGuard<'static, ()>),
305    Upgradable(parking_lot::RwLockUpgradableReadGuard<'static, ()>),
306    Write(parking_lot::RwLockWriteGuard<'static, ()>),
307}
308
309impl PrebuildGuard {
310    /// Acquire an upgradable lock (in-process upgradable read + file shared). `key` selects
311    /// the in-process lock and should identify `lock_path`.
312    pub fn lock_upgradable(lock_path: &Path, key: &str) -> Self {
313        let rw_guard = get_dep_lock(key).upgradable_read();
314        let lock_dir = lock_path.parent().unwrap().to_owned();
315        let file = fs::OpenOptions::new()
316            .read(true)
317            .write(true)
318            .create(true)
319            .truncate(false)
320            .open(lock_path)
321            .unwrap();
322        file.lock_shared().unwrap();
323        PrebuildGuard {
324            _rw_guard: RwGuard::Upgradable(rw_guard),
325            _global_guard: None,
326            _global_file: None,
327            _file: file,
328            lock_dir,
329        }
330    }
331
332    /// Upgrade to exclusive (in-process write + file exclusive + global locks).
333    pub fn upgrade(self) -> Self {
334        let file = self._file;
335        let rw_guard = match self._rw_guard {
336            RwGuard::Upgradable(u) => parking_lot::RwLockUpgradableReadGuard::upgrade(u),
337            _ => panic!("can only upgrade from upgradable"),
338        };
339        // Release per-key shared lock before acquiring global exclusive
340        // to avoid deadlock (other processes hold per-key shared and wait for global).
341        file.unlock().unwrap();
342        let global_guard = GLOBAL_PREBUILD_LOCK.write();
343        let global_file = fs::OpenOptions::new()
344            .read(true)
345            .write(true)
346            .create(true)
347            .truncate(false)
348            .open(self.lock_dir.join(".global-prebuild.lock"))
349            .unwrap();
350        global_file.lock().unwrap();
351        file.lock().unwrap();
352        PrebuildGuard {
353            _rw_guard: RwGuard::Write(rw_guard),
354            _global_guard: Some(global_guard),
355            _global_file: Some(global_file),
356            _file: file,
357            lock_dir: self.lock_dir,
358        }
359    }
360
361    /// Downgrade from exclusive to shared (releases global lock).
362    pub fn downgrade(self) -> Self {
363        let file = self._file;
364        file.lock_shared().unwrap();
365        let rw_guard = match self._rw_guard {
366            RwGuard::Write(w) => RwGuard::Read(parking_lot::RwLockWriteGuard::downgrade(w)),
367            RwGuard::Upgradable(u) => {
368                RwGuard::Read(parking_lot::RwLockUpgradableReadGuard::downgrade(u))
369            }
370            r @ RwGuard::Read(_) => r,
371        };
372        PrebuildGuard {
373            _rw_guard: rw_guard,
374            _global_guard: None,
375            _global_file: None,
376            _file: file,
377            lock_dir: self.lock_dir,
378        }
379    }
380
381    /// Get mutable access to the underlying file (for writing timestamps).
382    pub fn file_mut(&mut self) -> &mut fs::File {
383        &mut self._file
384    }
385}

391/// Set up a job directory with symlinked .fingerprint and deps subdirs.
392/// Does NOT set up build/ — use `populate_job_build_dir` for final builds
393/// or manually symlink for prebuild.
394///
395/// The `.fingerprint` and `deps` symlinks are what shares prebuilt state under
396/// the [`BuildDirLayout::Legacy`] layout. Under [`BuildDirLayout::New`] cargo
397/// ignores both directories (everything lives under `build/`), so the symlinks
398/// are harmless; they are created unconditionally because the layout is not
399/// yet known when job dirs are set up (detection happens during the prebuild).
400pub fn setup_job_dir(jobs_dir: &Path, name: &str, shared_debug: &Path) -> PathBuf {
401    let job = jobs_dir.join(name);
402    let _lock = get_job_dir_lock(&job);
403    let _lock = _lock.lock().unwrap();
404
405    // File lock for cross-process serialization on the same job dir.
406    fs::create_dir_all(&job).unwrap();
407    let job_lock_file = fs::OpenOptions::new()
408        .read(true)
409        .write(true)
410        .create(true)
411        .truncate(false)
412        .open(job.join(".job.lock"))
413        .unwrap();
414    job_lock_file.lock().unwrap();
415
416    let job_debug = job.join("debug");
417    fs::create_dir_all(&job_debug).unwrap();
418    for subdir in [".fingerprint", "deps"] {
419        let link = job_debug.join(subdir);
420        if !link.exists() {
421            let target = shared_debug.join(subdir);
422            fs::create_dir_all(&target).unwrap();
423            #[cfg(unix)]
424            std::os::unix::fs::symlink(&target, &link).unwrap();
425            #[cfg(windows)]
426            std::os::windows::fs::symlink_dir(&target, &link).unwrap();
427        }
428    }
429    job
430}

432/// Symlink the build/ directory for prebuild jobs (writes through to shared).

434    let link = prebuild_target.join("debug").join("build");

437        fs::create_dir_all(&target).unwrap();
438        #[cfg(unix)]

442    }
443}

451/// Populate the per-job build/ directory from the shared build/ directory.
452/// Returns a guard that holds the job lock — keep alive for the entire final build.
453/// This prevents races between processes building the same job concurrently.
454///
455/// The shared `build/` is mirrored two levels deep: each top-level directory is
456/// recreated job-locally and its *children* are symlinked to the shared copies.
457/// Anything the final build reads is the prebuilt, immutable shared state;
458/// anything it *creates or replaces* lands in the job-local directory instead
459/// of racing other jobs. This is the same structure under both layouts:
460///
461/// - **Legacy** (`build/<pkg>-<hash>/{build-script-build,out,output,...}`):
462///   cargo re-links `build-script-build` even on fresh builds; with per-child
463///   symlinks that replaces the job-local link, not the shared file.
464/// - **New** (`build/<pkg>/<unit-hash>/{fingerprint,out,run}`): the final
465///   build's own example unit is created job-locally. This matters because
466///   concurrent jobs can compile the *same* cargo unit — the simulator builds
467///   the fixed `sim-dylib` example in every job (varied only via
468///   `include!(env!(..))`, which affects freshness but not the unit hash) — so
469///   sharing `build/` wholesale would have them write, and uplift, the same
470///   `out/` files.
471pub fn populate_job_build_dir(job_debug: &Path, shared_debug: &Path) -> JobBuildGuard {
472    let shared_build = shared_debug.join("build");
473    let job_build = job_debug.join("build");
474
475    let job_dir = job_debug.parent().unwrap();
476    let mutex_guard = get_job_dir_lock(job_dir);
477    let mutex_guard = mutex_guard.lock().unwrap();
478
479    // Also hold a file lock for cross-process serialization on the same job dir.
480    let job_lock_path = job_dir.join(".job.lock");
481    let job_lock_file = fs::OpenOptions::new()
482        .read(true)
483        .write(true)
484        .create(true)
485        .truncate(false)
486        .open(&job_lock_path)
487        .unwrap();
488    job_lock_file.lock().unwrap();
489
490    // A stale symlink may be left over from an earlier version that shared
491    // `build/` wholesale; `remove_dir_all` would follow it into the shared dir.
492    if job_build.symlink_metadata().is_ok_and(|m| m.is_symlink()) {
493        let _ = fs::remove_file(&job_build);
494    } else {
495        let _ = fs::remove_dir_all(&job_build);
496    }
497    fs::create_dir_all(&job_build).unwrap();
498    if shared_build.exists() {
499        for entry in fs::read_dir(&shared_build).unwrap() {
500            let entry = entry.unwrap();
501            if !entry.file_type().unwrap().is_dir() {
502                continue;
503            }
504            let dest = job_build.join(entry.file_name());
505            fs::create_dir_all(&dest).unwrap();
506            for file in fs::read_dir(entry.path()).unwrap() {
507                let file = file.unwrap();
508                let file_dest = dest.join(file.file_name());
509                #[cfg(unix)]
510                std::os::unix::fs::symlink(file.path(), &file_dest).unwrap();
511                #[cfg(windows)]
512                {
513                    if file.file_type().unwrap().is_dir() {
514                        std::os::windows::fs::symlink_dir(file.path(), &file_dest).unwrap();
515                    } else {
516                        std::os::windows::fs::symlink_file(file.path(), &file_dest).unwrap();
517                    }
518                }
519            }
520        }
521    }
522
523    JobBuildGuard {
524        _mutex_guard: mutex_guard,
525        _file: job_lock_file,
526    }
527}

533/// The verbose version (`rustc -vV`) of the compiler child `cargo` invocations will use,
534/// honoring the `RUSTC` override like cargo does.
535static RUSTC_VERBOSE_VERSION: LazyLock<String> = LazyLock::new(|| {
536    let rustc = std::env::var_os("RUSTC").unwrap_or_else(|| "rustc".into());
537    let output = std::process::Command::new(rustc)
538        .arg("-vV")
539        .output()
540        .expect("failed to run `rustc -vV`");
541    assert!(output.status.success(), "`rustc -vV` failed");
542    String::from_utf8(output.stdout).unwrap()
543});
544
545fn hash_hex(hash: impl FnOnce(&mut DefaultHasher)) -> String {
546    let mut hasher = DefaultHasher::new();
547    hash(&mut hasher);
548    format!("{:016x}", hasher.finish())
549}

551/// Fingerprint of the compilation *environment* a child build runs under: the rustflags (in
552/// any stable encoding) and the compiler's verbose version.
553///
554/// Cargo keys the filenames of rlibs on both of these, so different fingerprints never
555/// collide in the shared `deps/` and can be cached side by side. It strips that key from
556/// dylib filenames unless `__CARGO_DEFAULT_LIB_METADATA` is set, so without that variable the
557/// trybuild dylib bakes this fingerprint into its target name instead (see [`dylib_lib_name`]).
558pub fn toolchain_fingerprint(rustflags: &str) -> String {
559    hash_hex(|h| {
560        rustflags.hash(h);
561        RUSTC_VERBOSE_VERSION.hash(h);
562    })
563}
564
565/// Whether cargo hashes the filenames of path-package dylibs. Cargo normally keeps those
566/// stable (`libfoo.so`) so executables can embed them; the undocumented
567/// `__CARGO_DEFAULT_LIB_METADATA` variable — which rust-lang/rust's bootstrap uses to build
568/// libstd — forces the metadata hash onto them too, making every configuration's dylib a
569/// distinct file.
570fn lib_metadata_enabled() -> bool {
571    std::env::var_os("__CARGO_DEFAULT_LIB_METADATA").is_some()
572}
573
574/// The `[lib] name` of the trybuild dylib package `package_name` when built under `rustflags`.
575///
576/// With `__CARGO_DEFAULT_LIB_METADATA` set this is cargo's default (the package name with
577/// `-` replaced by `_`): cargo already hashes the filename per configuration, so the manifest
578/// never needs to change. Without it the [`toolchain_fingerprint`] is appended so that
579/// configurations get distinct `lib{name}.so` files and cache side by side instead of
580/// clobbering one another. Features are not part of the name: they vary per build against one
581/// shared manifest, and the prebuild lock already serializes feature switches.
582pub fn dylib_lib_name(package_name: &str, rustflags: &str) -> String {
583    let default = package_name.replace('-', "_");
584    if lib_metadata_enabled() {
585        default
586    } else {
587        format!("{default}_{}", toolchain_fingerprint(rustflags))
588    }
589}

591/// Exclusive file lock on a trybuild project's `.hydro-trybuild-lock`, serializing all writes
592/// to the project's generated files (manifests, sources) across processes. Released on drop.
593pub fn lock_project(project_dir: &Path) -> fs::File {
594    let file = fs::File::create(project_dir.join(".hydro-trybuild-lock")).unwrap();
595    file.lock().unwrap();
596    file
597}

611/// Directories that a dynamically linked artifact built into the per-job artifact dir
612/// `job_debug` (e.g. `jobs/<name>/debug`) needs on its library search path (rpath or
613/// `LD_LIBRARY_PATH`) to load the trybuild dylib whose cargo package is `dylib_package_name`.
614/// `shared_debug` is the shared target's `debug/` that the job mirrors.
615///
616/// Every returned path must stay valid for the artifact's whole lifetime, which outlives the
617/// build (the binary is exec'd by the deployment later; the simulator `dlopen`s its cdylib after
618/// the build returns). Job dirs are keyed by generated-source hash, so tests whose programs are
619/// identical share one; a later build in the same job dir repopulates its `build/` (see
620/// [`populate_job_build_dir`]), so nothing under `job_debug/build/` may be referenced. The
621/// dylib's home is instead the shared prebuilt state, which only changes under the exclusive
622/// prebuild lock.
623///
624/// Cargo uplifts the dylib into `job_debug` under its unhashed `lib<name>.so` filename, which
625/// satisfies the loader whenever the artifact links against that name. With
626/// `__CARGO_DEFAULT_LIB_METADATA` set, however, the artifact links against the hash-suffixed
627/// `lib<name>-<hash>.so`:
628///
629/// - under the legacy layout every variant, hashed or not, lives in `deps/`, which
630///   `job_debug/deps` symlinks to once at job setup;
631/// - under the new layout `deps/` no longer exists and the uplift is *renamed* to the unhashed
632///   name, so the hashed file only exists in the dylib unit's
633///   `<shared_debug>/build/<dylib_package_name>/<hash>/out/` dir. Every such unit dir is
634///   included; hashed names are unique per unit so this is unambiguous, and unhashed names
635///   resolve from `job_debug` (listed first) before any unit dir.
636pub fn dylib_search_dirs(
637    dylib_package_name: &str,
638    job_debug: &Path,
639    shared_debug: &Path,
640) -> Vec<PathBuf> {
641    let mut dirs = vec![job_debug.to_owned()];
642    match build_dir_layout() {
643        BuildDirLayout::Legacy => dirs.push(job_debug.join("deps")),
644        BuildDirLayout::New => {
645            if let Ok(units) = fs::read_dir(shared_debug.join("build").join(dylib_package_name)) {
646                let mut out_dirs: Vec<PathBuf> = units
647                    .flatten()
648                    .map(|unit| unit.path().join("out"))
649                    .filter(|out| out.is_dir())
650                    .collect();
651                out_dirs.sort();
652                dirs.extend(out_dirs);
653            }
654        }
655    }
656    dirs
657}

659/// The `[lib] name` currently in the dylib manifest of the trybuild project at `project_dir`,
660/// if it has one. Call with [`lock_project`] held and write the manifest under the same lock.
661///
662/// Manifest generation must reuse this rather than compute a fresh name: the name only ever
663/// changes under the exclusive prebuild lock (see [`run_prebuild`]), which is what guarantees
664/// no in-flight final build links against a dylib named for another configuration.
665pub fn current_dylib_lib_name(project_dir: &Path) -> Option<String> {
666    let doc = read_manifest(&dylib_manifest_path(project_dir))?;
667    manifest_lib_name(&doc).map(str::to_owned)
668}

670/// Point the project's dylib manifest at the [`dylib_lib_name`] for `rustflags`.
671///
672/// Dylib builds call this first thing in their [`run_prebuild`] `build_fn`, i.e. under the
673/// exclusive prebuild lock, once no in-flight final build links the old name. It takes
674/// [`lock_project`] so a concurrent manifest regeneration cannot read the old name and write it
675/// back over the new one.
676pub fn set_dylib_lib_name(project_dir: &Path, rustflags: &str) {
677    let _project_lock = lock_project(project_dir);
678    let manifest = dylib_manifest_path(project_dir);
679    let mut doc = read_manifest(&manifest).expect("dylib manifest must exist before prebuild");
680    let package_name = doc["package"]["name"].as_str().unwrap();
681    let lib_name = dylib_lib_name(package_name, rustflags);
682    if manifest_lib_name(&doc) != Some(&lib_name) {
683        doc["lib"]["name"] = toml_edit::value(lib_name);
684        fs::write(&manifest, doc.to_string()).unwrap();
685    }
686}

688/// Run the prebuild phase with proper locking and freshness checking.
689///
690/// - `target_dir`: the shared target directory (e.g. `target/`)
691/// - `crate_name`: unique identifier for the crate being built (included in hash)
692/// - `features`: list of features for hashing
693/// - `rustflags`: the rustflags the prebuild (and the final builds sharing its artifacts) are
694///   compiled with; see [`toolchain_fingerprint`]
695/// - `staged_paths`: paths to check mtime against for freshness
696/// - `build_fn`: closure called with `prebuild_target` path under the exclusive lock; should
697///   run cargo build(s), and for dylib projects first call [`set_dylib_lib_name`]
698///
699/// Returns `(PrebuildGuard, CargoBuildLock)` both held in shared mode.
700/// Caller should keep both alive during the final build.
701///
702/// # Locking and freshness
703///
704/// Cargo itself supports one build per target dir; the per-job target dirs sidestep that, so
705/// concurrent builds are safe only while everything they both write has a distinct filename.
706/// Cargo hashes rustflags, compiler version and features into every filename except a path
707/// package's dylib (unless `__CARGO_DEFAULT_LIB_METADATA` is set), so the dylib and the
708/// manifest naming it are the one shared resource:
709///
710/// - Without `__CARGO_DEFAULT_LIB_METADATA` there is a single `.prebuild.lock`. Every build
711///   holds it shared through its final build; switching configuration takes it exclusive,
712///   which waits for all in-flight builds to finish before `build_fn` renames the manifest and
713///   rebuilds the prebuild. A fresh stamp therefore implies the manifest names this
714///   configuration's dylib.
715/// - With it, cargo names every configuration's files distinctly and the manifest is constant,
716///   so builds only need to serialize with others of the same `(crate, features, fingerprint)`
717///   — one `.prebuild-<key>.lock` each — and configurations never wait on one another.
718///
719/// Running builds with and without the variable against one target dir is unsupported: they
720/// would rename the shared manifest under different locks.
721///
722/// The freshness stamp stored in the lock file covers crate, features and fingerprint, so a
723/// prebuild for a different configuration is never mistaken for fresh.
724pub fn run_prebuild(
725    target_dir: &Path,
726    crate_name: &str,
727    features: &[String],
728    rustflags: &str,
729    staged_paths: &[PathBuf],
730    build_fn: impl FnOnce(&Path),
731) -> (PrebuildGuard, CargoBuildLock) {
732    // Acquire cargo build lock shared for the entire prebuild + final build duration.
733    let shared_debug = target_dir.join("debug");
734    fs::create_dir_all(&shared_debug).ok();
735    let cargo_lock = CargoBuildLock::lock_shared(&shared_debug.join(".cargo-build-lock"));
736
737    let toolchain = toolchain_fingerprint(rustflags);
738    let fingerprint = hash_hex(|h| {
739        crate_name.hash(h);
740        let mut sorted = features.to_vec();
741        sorted.sort();
742        sorted.hash(h);
743        toolchain.hash(h);
744    });
745
746    // Without `__CARGO_DEFAULT_LIB_METADATA` every configuration shares one fixed key, so this
747    // lock doubles as the global one: a configuration switch (exclusive) drains every in-flight
748    // build, not just those of the same configuration. `.global-prebuild.lock` (taken in
749    // `upgrade`) only adds anything in the per-key case, where it keeps two configurations from
750    // running their `cargo build`s into the shared `deps/` at the same time.
751    let lock_key = if lib_metadata_enabled() {
752        format!("prebuild-{fingerprint}")
753    } else {
754        "prebuild".to_owned()
755    };
756    let lock_path = target_dir.join(format!(".{lock_key}.lock"));
757
758    let staged_mtime = staged_paths
759        .iter()
760        .filter_map(|p| fs::metadata(p).and_then(|m| m.modified()).ok())
761        .max()
762        .unwrap_or(SystemTime::UNIX_EPOCH);
763
764    // The stamp's freshness also covers the build-dir layout: layout changes
765    // require a toolchain change, which also changes the mtime of
766    // `current_exe`, which callers include in `staged_paths`.
767    let prebuild_is_fresh = |path: &Path, expected_hash: &str| -> bool {
768        fs::read_to_string(path)
769            .ok()
770            .and_then(|s| {
771                let mut parts = s.trim().splitn(2, ':');
772                let hash = parts.next()?;
773                let nanos = parts.next()?.parse::<u128>().ok()?;
774                let ts = SystemTime::UNIX_EPOCH
775                    .checked_add(std::time::Duration::from_nanos(nanos as u64))?;
776                Some((hash.to_owned(), ts))
777            })
778            .is_some_and(|(hash, ts)| hash == expected_hash && ts >= staged_mtime)
779    };
780
781    log_build_event(
782        target_dir,
783        &format!("prebuild: lock_upgradable, lock_key={lock_key}, fingerprint={fingerprint}"),
784    );
785    let guard = PrebuildGuard::lock_upgradable(&lock_path, &lock_key);
786    if prebuild_is_fresh(&lock_path, &fingerprint) {
787        log_build_event(target_dir, "prebuild: fresh, downgrading to shared");
788        return (guard.downgrade(), cargo_lock);
789    }
790
791    log_build_event(target_dir, "prebuild: not fresh, upgrading to exclusive");
792    let mut guard = guard.upgrade();
793    log_build_event(target_dir, "prebuild: exclusive acquired");
794
795    // Re-check after acquiring exclusive.
796    if !prebuild_is_fresh(&lock_path, &fingerprint) {
797        let shared_debug = target_dir.join("debug");
798        let jobs_dir = target_dir.join("jobs");
799        let prebuild_target = setup_job_dir(&jobs_dir, "prebuild", &shared_debug);
800        symlink_prebuild_build_dir(&prebuild_target, &shared_debug);
801
802        build_fn(&prebuild_target);
803
804        // Write fingerprint:timestamp.
805        use std::io::Seek;
806        let now_nanos = SystemTime::now()
807            .duration_since(SystemTime::UNIX_EPOCH)
808            .unwrap()
809            .as_nanos();
810        let file = guard.file_mut();
811        file.set_len(0).unwrap();
812        file.seek(std::io::SeekFrom::Start(0)).unwrap();
813        write!(file, "{}:{}", fingerprint, now_nanos).unwrap();
814    }
815
816    (guard.downgrade(), cargo_lock)
817}
