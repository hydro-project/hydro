6/// Given an _unbounded_ input stream, retains the **latest** value across ticks (last-write-wins)
7/// and emits it (as a clone) every time the loop fires, without causing the loop to fire.
8///
9/// Like `batch_lazy()`, this operator does NOT cause the loop to fire. But unlike `batch_lazy()`
10/// — which drops its pending data at the end of any tick where the loop does not fire —
11/// `snapshot()` holds the most recent value in a single cell that persists across ticks. Each
12/// newly arriving value *replaces* (and drops) the previous one, so at most one value is retained
13/// no matter how many ticks pass before the loop fires. Older values superseded by a newer one are
14/// never observed.
15///
16/// The retained value is **not consumed** when the loop fires: `snapshot()` is a persistent view
17/// of the latest value, so if the loop fires again (e.g. triggered by a `batch()` input) without
18/// any new input to `snapshot()`, the same value is observed again. The item type must therefore
19/// implement `Clone`. Before any value has arrived, `snapshot()` emits nothing.
20///
21/// This makes `snapshot()` the right ingress for *state observation* feeds (e.g. a stream of
22/// the current value of some state being snapshotted by the loop): the observer only ever cares
23/// about the latest value, and must never be left permanently stale by a dropped update.
24///
25/// `snapshot()` is one of the loop-ingress ("windowing") operators, which differ in whether they
26/// cause the surrounding `loop { ... }` to fire and whether pending data is retained:
27/// - `batch()` triggers the loop only when its windowed input is non-empty.
28/// - `batch_lazy()` never triggers the loop on its own; its data is only observed if the loop
29///   fires for some other reason (otherwise dropped at tick end).
30/// - `batch_eager()` always triggers the loop, even when the windowed input is empty.
31/// - `snapshot()` never triggers the loop on its own, but retains the latest value
32///   (last-write-wins) across ticks and emits it every time the loop fires.
33/// - `snapshot_keyed()` never triggers the loop on its own, but retains the latest value *per
34///   key* (from `(K, Option<V>)` updates) across ticks and emits every entry every time the loop
35///   fires.
36/// - `snapshot_prefix()` never triggers the loop on its own, but retains every element received
37///   so far across ticks and replays the whole prefix every time the loop fires.
38///
39/// `snapshot()` holds a single item. To snapshot keyed state (one entry per item), use
40/// `snapshot_keyed()`, which retains the latest value *per key*. To replay every element received
41/// so far (e.g. a bounded input), use `snapshot_prefix()`.
42///
43/// Memory note: because only the single latest value is retained, memory use is bounded
44/// regardless of how often the producer emits or how long the loop goes without firing.
45///
46/// `snapshot()` is only valid at the entry of a root-level loop: nested loops iterate to fixpoint
47/// within a single tick, so cross-tick retention does not apply to them.
48///
49/// ```dfir
50/// trigger = source_iter([(), ()]);
51/// updates = source_iter([1, 2, 3]);
52/// loop {
53///     trigger -> batch() -> for_each(std::mem::drop);
54///     // Only the latest value, `3`, is observed.
55///     updates -> snapshot() -> for_each(|x| println!("{}", x));
56/// };
57/// ```
58pub const SNAPSHOT: OperatorConstraints = OperatorConstraints {
59    name: "snapshot",
60    categories: &[OperatorCategory::Windowing],
61    hard_range_inn: RANGE_1,
62    soft_range_inn: RANGE_1,
63    hard_range_out: RANGE_1,
64    soft_range_out: RANGE_1,
65    num_args: 0,
66    persistence_args: RANGE_0,
67    type_args: RANGE_0,
68    is_external_input: false,
69    flo_type: Some(FloType::WindowingRetain),
70    ports_inn: None,
71    ports_out: None,
72    input_delaytype_fn: |_| None,
73    // Same as batch() — identity in inline codegen. The retention behavior comes from the
74    // handoff feeding this operator being declared outside the tick closure as a single
75    // last-write-wins `Option<T>` cell (rather than a tick-local bump-allocated vec), so the
76    // latest value survives ticks where the loop does not fire, newer values replace (drop)
77    // older ones, and the loop reads a clone (not consuming the cell) each time it fires.
78    // See `DfirGraph::as_code_with_options`.
79    write_fn: |wc @ &WriteContextArgs { .. }, _diagnostics| {
80        let write_iterator = identity_write_iterator_fn(wc);
81        Ok(OperatorWriteOutput {
82            write_prologue: Default::default(),
83            write_iterator,
84            write_iterator_after: Default::default(),
85            write_tick_end: Default::default(),
86        })
87    },
88};
