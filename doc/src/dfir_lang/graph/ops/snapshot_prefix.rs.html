6/// Given an _unbounded_ input stream, retains **every** element received so far in a persistent
7/// buffer across ticks, and emits the whole prefix (as clones, in arrival order) every time the
8/// loop fires, without causing the loop to fire.
9///
10/// Like `batch_lazy()` and `snapshot()`, this operator does NOT cause the loop to fire. Unlike
11/// `batch_lazy()` — which drops its pending data at the end of any tick where the loop does not
12/// fire — nothing is ever dropped: each arriving element is appended to a buffer that persists
13/// across ticks. And unlike `snapshot()` — which holds only the single latest value —
14/// `snapshot_prefix()` keeps all of them.
15///
16/// The buffer is **not consumed** when the loop fires: `snapshot_prefix()` is a persistent view
17/// of the stream's prefix up to now, so if the loop fires again (e.g. triggered by a `batch()`
18/// input) without any new input, the same prefix is replayed. The item type must therefore
19/// implement `Clone`. Before any element has arrived, `snapshot_prefix()` emits nothing.
20///
21/// This is the right ingress for replaying a *bounded* input (e.g. a `source_iter(..)` or a
22/// bounded collection) into a loop that is driven by some other input: it is equivalent to
23/// `persist::<'static>() -> batch_lazy()`, except that it does not need a `persist` at the top
24/// level and does not depend on the replay arriving in the same tick that the loop fires.
25///
26/// Memory note: the retained buffer grows with the total number of elements received, and is
27/// never truncated. `snapshot_prefix()` is intended for bounded inputs; for an unbounded
28/// emit-on-change feed where only the latest value matters, use `snapshot()` (or
29/// `snapshot_keyed()` for per-key state).
30///
31/// `snapshot_prefix()` is one of the loop-ingress ("windowing") operators, which differ in whether
32/// they cause the surrounding `loop { ... }` to fire and whether pending data is retained:
33/// - `batch()` triggers the loop only when its windowed input is non-empty.
34/// - `batch_lazy()` never triggers the loop on its own; its data is only observed if the loop
35///   fires for some other reason (otherwise dropped at tick end).
36/// - `batch_eager()` always triggers the loop, even when the windowed input is empty.
37/// - `snapshot()` never triggers the loop on its own, but retains the latest value
38///   (last-write-wins) across ticks and emits it every time the loop fires.
39/// - `snapshot_keyed()` never triggers the loop on its own, but retains the latest value *per
40///   key* (from `(K, Option<V>)` updates) across ticks and emits every entry every time the loop
41///   fires.
42/// - `snapshot_prefix()` never triggers the loop on its own, but retains every element received
43///   so far across ticks and replays the whole prefix every time the loop fires.
44///
45/// `snapshot_prefix()` is only valid at the entry of a root-level loop: nested loops iterate to
46/// fixpoint within a single tick, so cross-tick retention does not apply to them.
47///
48/// ```dfir
49/// trigger = source_iter([(), ()]);
50/// items = source_iter([1, 2, 3]);
51/// loop {
52///     trigger -> batch() -> for_each(std::mem::drop);
53///     // Observes `1`, `2`, `3` (every element received so far, in order).
54///     items -> snapshot_prefix() -> for_each(|x| println!("{}", x));
55/// };
56/// ```
57pub const SNAPSHOT_PREFIX: OperatorConstraints = OperatorConstraints {
58    name: "snapshot_prefix",
59    categories: &[OperatorCategory::Windowing],
60    hard_range_inn: RANGE_1,
61    soft_range_inn: RANGE_1,
62    hard_range_out: RANGE_1,
63    soft_range_out: RANGE_1,
64    num_args: 0,
65    persistence_args: RANGE_0,
66    type_args: RANGE_0,
67    is_external_input: false,
68    flo_type: Some(FloType::WindowingRetain),
69    ports_inn: None,
70    ports_out: None,
71    input_delaytype_fn: |_| None,
72    // Identity in inline codegen, like `snapshot()`. The retention behavior comes from the
73    // handoff feeding this operator being declared outside the tick closure as a persistent
74    // `std::vec::Vec<T>` (rather than a tick-local bump-allocated vec) that producers append to,
75    // and that the loop reads (cloning every element, not consuming the buffer) each time it
76    // fires. See `DfirGraph::as_code_with_options`.
77    write_fn: |wc @ &WriteContextArgs { .. }, _diagnostics| {
78        let write_iterator = identity_write_iterator_fn(wc);
79        Ok(OperatorWriteOutput {
80            write_prologue: Default::default(),
81            write_iterator,
82            write_iterator_after: Default::default(),
83            write_tick_end: Default::default(),
84        })
85    },
86};
